## L01 日本語で内容を読み取れる見出しにする

根拠の種類: 編集上の仮説（実画面で比較する）。対象: 日本語。

使う場面: 英語の大見出しや小さな日本語の副題からセクションの内容が分かりにくいとき。

英語の大見出しだけでセクションの内容を伝えず、日本語の見出しから用件を拾えるようにする。装飾の英語と情報の主役を区別する。

例: 「SERVICE」より先に「できること」を視覚的に認識できる案を比較する。

例外・注意: 英語の読者や固有のブランド表現を対象とする場合は優先言語に合わせる。

確認: 日本語の見出しだけを追ってページの流れが分かるか読む。

出典: [デジタル庁 レイアウト](https://design.digital.go.jp/dads/foundations/layout/)、[デジタル庁 リンクテキスト: アクセシビリティ](https://design.digital.go.jp/dads/foundations/link-text/accessibility/)

## L02 日本語の長い見出しから組む

根拠の種類: 編集上の仮説（実画面で比較する）。対象: 日本語。

使う場面: LP、記事、一覧、業務画面の情報のまとまりと、狭い画面の配置を決めるとき。

英単語数を前提にした巨大見出しを置き換える際は、日本語実文の行数と隣接要素の位置からサイズを選ぶ。

例: 「部署をまたいだ承認作業を、ひとつに。」をヒーローへ入れる。

例外・注意: 短い日本語を大きく見せる表現は選べる。見出しサイズに一律の上限は設けない。

確認: 狭いPC幅とスマホで、主要な説明や操作が見出しだけに押し流されないか確認する。

出典: [デジタル庁 タイポグラフィ](https://design.digital.go.jp/dads/foundations/typography/)、[デジタル庁 レイアウト](https://design.digital.go.jp/dads/foundations/layout/)

## L03 和文の行長を文字の幅から検討する

根拠の種類: 編集上の仮説（実画面で比較する）。対象: 日本語。

使う場面: 長文記事や説明欄の最大幅を指定するとき。chを日本語の文字数として扱わない。

chは主に欧文数字の幅に基づくため、日本語の行長へそのまま読み替えない。icや実文を使って比較する。

例: 長文の試作でmax-inline-size:40icを出発点にし、実際の読みやすさを見る。

例外・注意: 40文字を推奨規格や絶対値としない。混植ではicの値と実文字数がずれる。

確認: 同じ文章を複数の幅で読み、スマホでは画面幅を優先する。

出典: [W3C CSS Values: ic](https://www.w3.org/TR/css-values-4/#ic)、[W3C 日本語組版処理の要件](https://www.w3.org/TR/jlreq/)

## L04 余白で関連する情報をまとめる

根拠の種類: 公開実践（適用範囲を確認する）。対象: 全言語に共通。

使う場面: LP、記事、一覧、業務画面の情報のまとまりと、狭い画面の配置を決めるとき。

関連要素の間隔を、別のまとまりとの間隔より小さくする。見出しと本文、価格と条件を離し過ぎない。

例: 価格の直下に、対象プランと課金周期を置く。

例外・注意: グリッドの数値だけでまとまりは決まらない。罫線・背景・文字階層も確認する。

確認: スクロール中に、どの注記がどの項目に属するか迷わないか確認する。

出典: [デジタル庁 余白](https://design.digital.go.jp/dads/foundations/spacing/)

## L05 情報密度は利用場面から決める

根拠の種類: 編集上の仮説（実画面で比較する）。対象: 日本語で差が出やすい共通事項。

使う場面: LP、記事、一覧、業務画面の情報のまとまりと、狭い画面の配置を決めるとき。

日本人は高密度を好むと一括りにせず、比較する画面か読む画面かで密度を変える。余白だけを増やして階層の問題を隠さない。

例: 料金比較表とブランド紹介ページを別々に評価する。

例外・注意: 既存ユーザーの作業効率が重要な業務UIでは、読み物の余白量を強制しない。

確認: 必要情報を探す課題で、文字サイズ・グループ・スクロール量を比較する。

出典: [SmartHR デザイントークン: タイポグラフィ](https://smarthr.design/products/design-tokens/typography/)、[デジタル庁 レイアウト](https://design.digital.go.jp/dads/foundations/layout/)

## L06 同じカードでも日本語の文量差を受け止める

根拠の種類: 編集上の仮説（実画面で比較する）。対象: 日本語。

使う場面: LP、記事、一覧、業務画面の情報のまとまりと、狭い画面の配置を決めるとき。

短い英語のダミー文だけで高さを決めず、長い名称、複数行の説明、補足を入れる。本文の切り捨てで高さを合わせない。

例: 商品名が8文字と40文字のカードを並べる。

例外・注意: 一覧で省略が必要なら、全文を確認できる導線と識別に必要な情報を残す。

確認: 一件だけ長い場合と全件が長い場合の両方で確認する。

出典: [デジタル庁 レイアウト](https://design.digital.go.jp/dads/foundations/layout/)、[W3C WCAG 2.2 Understanding: Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

## L07 日本語ラベルの長さにボタンを合わせる

根拠の種類: 編集上の仮説（実画面で比較する）。対象: 日本語。

使う場面: LP、記事、一覧、業務画面の情報のまとまりと、狭い画面の配置を決めるとき。

固定幅・固定高で文字を押し込まず、横の余白と最小の高さから考える。長いラベルは文言と配置も見直す。

例: 「変更内容を確認する」と「保存する」を並べ、スマホでは縦積みも比較する。

例外・注意: 折り返すラベルを全て禁止しない。重要操作は全文が見えることを優先する。

確認: 通常・読込中・エラー時と文字拡大で、ラベルが欠けないか見る。

出典: [SmartHR Button](https://smarthr.design/products/components/button/)、[W3C WCAG 2.2 Understanding: Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

## L08 漢字の黒さを装飾量と合わせて調整する

根拠の種類: 編集上の仮説（実画面で比較する）。対象: 日本語。

使う場面: LP、記事、一覧、業務画面の情報のまとまりと、狭い画面の配置を決めるとき。

漢字を含む太字見出し、太い罫線、塗り面が重なるときは、文字サイズ・ウェイト・背景のどれで強弱を付けるか比較する。

例: すべてを700にせず、見出しと本文と補足の差を実文で見る。

例外・注意: 軽い字面を万能の美意識にしない。ブランドの力強さや可読性を優先する。

確認: 白黒にしても主要な情報が分かれ、細線が読めるか確認する。

出典: [デジタル庁 タイポグラフィ](https://design.digital.go.jp/dads/foundations/typography/)、[SmartHR デザイントークン: タイポグラフィ](https://smarthr.design/products/design-tokens/typography/)
