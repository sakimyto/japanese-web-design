# 追加スキルの評価課題

これは比較試験の手順と入力例。初期版では生成AIによる比較試験を実施していない。課題と期待値があることを、効果の証明として扱わない。

## 入力と出力

固定する入力は、ユーザーの制作依頼、実文、画面幅、利用環境、既存のデザインスキルとその版、モデルと設定、変更可能な範囲。追加スキルの有無以外は同じ条件にする。ブランドや元のコピーを変える場合は別の比較として扱う。

出力には、成果物、適用したルールID、非適用の理由、実行した確認、未確認事項を残す。既存のデザインスキルだけの結果と、補助スキルを併用した結果を保存する。生成のゆらぎを踏まえ、成功例だけを選んで公開しない。

## 判定を分ける

先に、情報の欠落、IME誤送信、主要操作の不能、原文の意図しない変更を確認する。該当する失敗が残る案は、見た目の高評価だけで採用しない。

視覚面は、日本語での情報の拾いやすさ、改行の自然さ、文字の密度、和欧混植、文言の理解、ブランドとの整合を別々に評価する。各軸を0〜2で記録する場合、0は具体的な支障あり、1は課題を解ける、2は比較対象より良いと説明できる状態とする。この尺度は自作であり、妥当性を検証した心理尺度ではない。

幅は320、375、768、1280 CSS pxを初期の比較集合とし、利用者の環境や既知の境界幅を追加する。文字拡大、字間変更、フォント取得失敗も扱う。コードの検査だけでブラウザ表示や実IMEを検証済みにしない。

日本語話者の評価者にはA/Bの名称と提示順を変えて見せ、次に何をすればよいと思うか、読みにくい箇所はどこか、その理由を聞く。人数と条件を記録する。初回の判断では、入力・表示の重大な回帰がないことと、主要な視覚軸で改善の理由を説明できることを確認する。必要な人数や統計的な検出力を未設計のまま、有意差や改善率を主張しない。

## 差分の記録

各差分を `intended`（意図した改善）、`regression`（回帰）、`unknown`（判断できない）へ分類する。課題ID、条件、変更前後、理由、ルールID、証拠の位置を保存する。`unknown` を改善として数えない。

資料の追加は、既存項目で扱えない具体的な失敗と結び付ける。基準を変更した場合は同じ8課題を再確認し、適用しなかった理由も残す。
