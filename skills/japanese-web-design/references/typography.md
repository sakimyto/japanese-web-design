# 書体と文字の密度

版: 1.0.0。資料確認日: 2026-11-08。

catalog.jsonから生成。数値の目安と公開実践は、用途に合わせて比較する。

## T01 日本語の実グリフで書体を選ぶ

根拠の種類: 公開実践（適用範囲を確認する）。対象: 日本語。

使う場面: 書体・文字サイズ・行高・ウェイトを選ぶとき。実際に使う日本語の見出しと本文で判断する。

欧文の見本だけで採用せず、漢字・かな・数字を含む本文で確認する。フォント指定が日本語に効いているかも調べる。

例: 「請求書を確認する」「あいうえお」「0123456789」を同じ画面に置く。

例外・注意: ブランド指定がある場合は候補を増やす前に、その書体の日本語対応を確かめる。

確認: 開発者ツールのRendered Fonts等で実際の書体を確認する。

出典: [デジタル庁 タイポグラフィ](https://design.digital.go.jp/dads/foundations/typography/)、[SmartHR 基本要素: タイポグラフィ](https://smarthr.design/basics/typography/)

## T02 OSごとのウェイト差を確認する

根拠の種類: 公開実践（適用範囲を確認する）。対象: 日本語で差が出やすい共通事項。

使う場面: 游ゴシックを採用する、またはWindowsで文字が細いという指摘があるとき。

同じfont-weightでも字面の濃さは一致しない。特に游ゴシックはMacの見た目だけで採用しない。

例: 本文400と見出し700をWindowsとmacOSで並べる。

例外・注意: 資料中のOS別フォント構成は永続的な保証ではない。実際の配信先で確認する。

確認: 漢字の細線、かなの太さ、ボタンラベルの判読性を比較する。

出典: [SmartHR ウェブサイトのタイポグラフィ](https://smarthr.design/basics/typography/website/)

## T03 本文サイズは用途から決める

根拠の種類: 編集上の仮説（実画面で比較する）。対象: 日本語で差が出やすい共通事項。

使う場面: 書体・文字サイズ・行高・ウェイトを選ぶとき。実際に使う日本語の見出しと本文で判断する。

初期検討では本文1rem前後から試し、文字の複雑さと読む距離に合わせる。16pxを法的な最低値や万能の答えとしない。

例: 記事本文と管理画面の表を同じサイズに固定せず、実文で比較する。

例外・注意: 既存のアクセシビリティ基準や利用者要件があれば優先する。

確認: 長文、補足、操作ラベルを通常表示と拡大表示で読む。

出典: [デジタル庁 タイポグラフィ](https://design.digital.go.jp/dads/foundations/typography/)、[SmartHR デザイントークン: タイポグラフィ](https://smarthr.design/products/design-tokens/typography/)

## T04 本文と見出しの行高を分ける

根拠の種類: 編集上の仮説（実画面で比較する）。対象: 日本語。

使う場面: 日本語の本文、二行以上の見出し、ルビのある段落に行高を設定するとき。

本文は1.6〜1.8、複数行見出しは1.3〜1.5を試す出発点とし、ルビ・サイズ・書体で調整する。

例: 英語向けのline-height:1を二行の日本語見出しに流用しない。

例外・注意: 短い一行ラベルや高密度の業務UIに同じ範囲を強制しない。

確認: 上下の漢字が接触せず、見出しが一つのまとまりに見えるか確認する。

出典: [デジタル庁 タイポグラフィ](https://design.digital.go.jp/dads/foundations/typography/)、[SmartHR デザイントークン: タイポグラフィ](https://smarthr.design/products/design-tokens/typography/)

## T05 本文の字間は標準から調整する

根拠の種類: 編集上の仮説（実画面で比較する）。対象: 日本語。

使う場面: 書体・文字サイズ・行高・ウェイトを選ぶとき。実際に使う日本語の見出しと本文で判断する。

letter-spacing:normalを基点にする。英語の大文字ラベル用の広い字間や、大見出しの強いマイナス字間を和文全体へ広げない。

例: 「利用料金」を0と0.12emで比較し、語のまとまりを見る。

例外・注意: 短い広告コピーの広い字間は表現として選べる。長文と設定を分ける。

確認: 句読点を含む段落で、字間が語のまとまりを壊していないか読む。

出典: [W3C CSS Text Level 3](https://www.w3.org/TR/css-text-3/)、[デジタル庁 タイポグラフィ](https://design.digital.go.jp/dads/foundations/typography/)

## T06 明朝体には用途を与える

根拠の種類: 編集上の仮説（実画面で比較する）。対象: 日本語。

使う場面: 書体・文字サイズ・行高・ウェイトを選ぶとき。実際に使う日本語の見出しと本文で判断する。

明朝体を和風の記号として一括適用せず、記事の語り口やブランドに合う箇所で選ぶ。小さなUIでは細線を確認する。

例: 編集記事の見出しは明朝、操作ラベルは読みやすいゴシックという案を比較する。

例外・注意: 明朝の本文も成立する。業種と書体だけを一対一で固定しない。

確認: 本文、注記、数字を各背景色と実サイズで読む。

出典: [SmartHR 基本要素: タイポグラフィ](https://smarthr.design/basics/typography/)、[デジタル庁 タイポグラフィ](https://design.digital.go.jp/dads/foundations/typography/)

## T07 和欧混植の大きさと基線を合わせる

根拠の種類: 編集上の仮説（実画面で比較する）。対象: 日本語で差が出やすい共通事項。

使う場面: 日本語と英字・数字を同じ行に置くとき。価格、日付、製品名を重点的に見る。

同じfont-sizeだけで揃ったと判断せず、英字の高さ、数字、かなの字面、基線を確認する。数字の強調は対象を限定する。

例: 「月額 3,000円」と「API連携」を同じ行で見る。

例外・注意: 価格や統計の数字を主役にする場合は意図した差を残す。

確認: 丸数字、括弧、通貨記号を含む行が不自然に上下しないか見る。

出典: [W3C 日本語組版処理の要件](https://www.w3.org/TR/jlreq/)、[SmartHR デザイントークン: タイポグラフィ](https://smarthr.design/products/design-tokens/typography/)

## T08 フォント配信をデザインの一部として確認する

根拠の種類: 公開実践（適用範囲を確認する）。対象: 日本語で差が出やすい共通事項。

使う場面: 書体・文字サイズ・行高・ウェイトを選ぶとき。実際に使う日本語の見出しと本文で判断する。

日本語Webフォントの転送量、必要なウェイト、表示中の代替書体を測る。swap指定だけで性能対策が完了したとしない。

例: 低速通信とフォント取得失敗で、本文とボタンの折り返しを見る。

例外・注意: フォントファイルを無許可で同梱しない。サブセットでは必要文字の欠落も確認する。

確認: 初回表示、読み込み後の移動、フォント失敗時の可読性を記録する。

出典: [Google web.dev Best practices for fonts](https://web.dev/articles/font-best-practices)、[SmartHR 基本要素: タイポグラフィ](https://smarthr.design/basics/typography/)
