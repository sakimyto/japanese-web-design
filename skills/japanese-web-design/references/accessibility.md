# 日本語の可読性とアクセシビリティ

## A01 淡い文字でも必要なコントラストを保つ

根拠の種類: 技術仕様・標準の解説。対象: 全言語に共通。

使う場面: 日本語の文字や操作を、拡大表示・読み上げ・異なる入力方法で確認するとき。

WCAGを確認する場合、通常の文字は4.5:1、大きな文字は3:1という条件と例外を区別する。日本語の細線は数値だけで読めたと判断しない。

例: 灰色の注記と細い明朝体を実サイズで確認する。

例外・注意: ロゴや非活性UI等の例外を確認する。日本語だけの特別な緩和基準を作らない。

確認: 背景との比を測り、実際の書体・サイズでも判読する。

出典: [W3C WCAG 2.2 Understanding: Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## A02 文字を拡大しても情報を失わない

根拠の種類: 技術仕様・標準の解説。対象: 日本語で差が出やすい共通事項。

使う場面: 日本語の文字や操作を、拡大表示・読み上げ・異なる入力方法で確認するとき。

横書きでは320 CSS px相当の幅で、不要な横スクロールや文字の欠落を確認する。固定高の見出し・ボタン・カードを重点的に見る。

例: 長い日本語見出しと入力エラーを出した画面を拡大する。

例外・注意: 二次元の表など例外がある。幅の検査だけで全アクセシビリティ適合とは言わない。

確認: 画面幅と拡大条件を記録し、主要な操作まで完了する。

出典: [W3C WCAG 2.2 Understanding: Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

## A03 文字間隔の変更を受け止める

根拠の種類: 技術仕様・標準の解説。対象: 日本語で差が出やすい共通事項。

使う場面: 固定高の部品や省略処理があり、利用者が行高・字間を変更する可能性があるとき。

利用者の行高・段落・字間変更で内容が欠けないことを確認する。WCAGの検査値をデザインの既定値にする義務と読み違えない。

例: 日本語本文、ボタン、補足を、字間0.12em等の変更で確認する。

例外・注意: 単語間隔等を使わない言語・文字体系には適用可能な項目で確認する。

確認: 固定高とoverflow:hiddenによる切り捨て、操作の重なりを確認する。

出典: [W3C WCAG 2.2 Understanding: Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)

## A04 本文を画像だけで渡さない

根拠の種類: 技術仕様・標準の解説。対象: 日本語で差が出やすい共通事項。

使う場面: 日本語の文字や操作を、拡大表示・読み上げ・異なる入力方法で確認するとき。

技術で表せる文字はテキストを使う。日本語のコピーを画像にする場合は、必要性と代替テキストを確認する。

例: 料金や申込条件を画像バナー内だけに入れない。

例外・注意: ロゴなど、表現自体が情報の伝達に必要な場合には例外がある。全ての文字入り画像を一律に禁止しない。

確認: 画像の非表示、拡大、読み上げでも必要な条件を取得できるか確認する。

出典: [W3C WCAG 2.2 Understanding: Images of Text](https://www.w3.org/WAI/WCAG22/Understanding/images-of-text.html)

## A05 言語の指定を読み上げと照合する

根拠の種類: 技術仕様・標準の解説。対象: 日本語で差が出やすい共通事項。

使う場面: 日本語の文字や操作を、拡大表示・読み上げ・異なる入力方法で確認するとき。

ページの主言語を示し、まとまった別言語の部分は必要に応じて区別する。日本語を見せてlang=enのままにしない。

例: 日本語本文と英語の引用を、各内容に合うlangで扱う。

例外・注意: 製品名や短い外来語の一つずつに機械的なlang切替を付けない。

確認: 実機の読み上げで、言語と語順が意図どおりか確認する。

出典: [W3C WCAG 2.2 Understanding: Language of Page](https://www.w3.org/WAI/WCAG22/Understanding/language-of-page.html)、[W3C Declaring language in HTML](https://www.w3.org/International/questions/qa-html-language-declarations)

## A06 ルビや装飾文字の読み上げを実測する

根拠の種類: 編集上の仮説（実画面で比較する）。対象: 日本語。

使う場面: 日本語の文字や操作を、拡大表示・読み上げ・異なる入力方法で確認するとき。

見た目を整えたルビ、縦書き、英語の飾り見出しが、本文の重複読みや順序の混乱を起こさないか確認する。

例: 可視の日本語見出しと飾りの英語を、意味を重ねず伝える。

例外・注意: aria-hiddenで意味のある文字まで隠さない。スクリーンリーダー間の差を残す。

確認: VoiceOver等の対象環境で見出し移動と連続読みを確認する。

出典: [WHATWG HTML ruby](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-ruby-element)、[W3C WCAG 2.2 Understanding: Language of Page](https://www.w3.org/WAI/WCAG22/Understanding/language-of-page.html)

## A07 タップ領域の基準を混同しない

根拠の種類: 技術仕様・標準の解説。対象: 全言語に共通。

使う場面: 日本語の文字や操作を、拡大表示・読み上げ・異なる入力方法で確認するとき。

WCAG 2.2 AAの最小ターゲットは24 CSS pxの基準と間隔等の例外を含む。44pxを全てのAA必須条件と書かない。

例: 小さい「変更」リンクが密集する行で、領域と間隔を確認する。

例外・注意: 本文内リンク等の例外がある。推奨する余裕と適合基準を分ける。

確認: 領域の寸法と間隔を測り、指やキーボードで操作する。

出典: [W3C WCAG 2.2 Understanding: Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

## A08 フォームのエラーを落ち着いて確認できるようにする

根拠の種類: 公開実践（適用範囲を確認する）。対象: 日本語で差が出やすい共通事項。

使う場面: 日本語の文字や操作を、拡大表示・読み上げ・異なる入力方法で確認するとき。

日本語の変換中にエラーを毎回読み上げたり、表示が動いたりしないようにする。ラベル・説明・エラーを関連付け、送信後に到達できるようにする。

例: 未入力で送信した後、対象欄と修正方法へ進めるようにする。

例外・注意: aria-liveをすべてのエラーへ一律に付けない。検証時点と読み上げの重複を実測する。

確認: 変換中、送信後、修正後、複数エラーを読み上げと画面の両方で確認する。

出典: [デジタル庁 インプットテキスト: アクセシビリティ](https://design.digital.go.jp/dads/components/input-text/accessibility/)、[SmartHR エラーメッセージ](https://smarthr.design/products/contents/error-messages/)
