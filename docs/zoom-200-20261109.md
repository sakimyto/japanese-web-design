# 追加Labの200%拡大を確認する

本人の2026-11-09の依頼に基づく。前回はviewportの指定中に拡大キーを送っても倍率が変わらず、200%を未確認とした。今回はviewport上書きを使わず、既存Chrome本体で対象タブを選び、実際の拡大操作を行う。見た目の大きさや指定値だけで成功としない。

## 仕様と観測

- Z200: Chrome本体の200%表示、変更前後のdevicePixelRatioが2倍、innerWidthとinnerHeightが約半分の3点を照合する。値は有限・正数で、同じ公開URLの比較であることを要求する。
- ZCONTENT: 横スクロール、実テキスト矩形の画面外へのはみ出し、hidden/clipの祖先による欠けがない。スクロールで到達できる縦方向の長さは欠けと扱わない。意図した比較見本や折りたたみの文は削らない。
- ZACTION: ヘッダー・フィルター・検索・詳細・コピーへ到達でき、検索の交差・0件・リセット・詳細開閉・コピーが同じ意味で動く。主要操作は44 CSS px以上を保つ。
- ZPRESERVE: 本文・出典・head・URL・導入コマンド・ZIP・タグを保持する。崩れがあれば同じ条件で再現して最小修正し、必要な検査・CI・本番反映後に同じ操作を再確認する。

最初の観測では、100%の1920×873 CSS px・DPR2から、Chromeのズーム表示200%、960×436 CSS px・DPR4へ変わった。画面全体の横はみ出しは0。その後、本文と長い詳細、検索・コピーまで同じ実倍率で確認した。ページ全体の実ズームを検査するもので、OSの文字設定や文字だけの拡大、別OS・別ブラウザの保証には広げない。

## 検査方法と反例

同じDOMから得た実測値を小さな判定器へ渡す。正常な200%の正例、100%のまま、DPRだけを変えた偽装、viewportだけを半分にした状態、不正値、欠け・はみ出しを拒否する負例を保持する。有限の入力と実DOMの矩形なので、SMT/TLA+の新しい状態モデルは追加しない。判定器のテストだけをブラウザ確認の成功と扱わない。

ブラウザの標準的な範囲APIで、表示される全テキストの矩形を調べる。閉じた詳細や非表示の補助文は矩形がないため除き、代表的な長い詳細を開いた状態も同じ判定へ渡す。前回と同じ表示検査・内容の固定比較・必須build/testを使う。拡大操作後は作成したタブだけを閉じ、対象サイトの倍率を元へ戻す。

## 確認結果

2026-11-09、公開中のcommit 8cdbbdbdを実Chromeで確認した。拡大率200%の表示、DPR2→4、1920×873→960×436 CSS pxの変化が一致した。viewport上書きは使っていない。100%のまま・DPRだけの変更・viewportだけの変更という3つの反例を同じ倍率判定が拒否し、幅・高さ・DPRの0/負数/NaN/Infinityは全24通りを拒否した。

通常状態は282テキストノード・296矩形、内容の長いC06/R06/T08を開いた状態は328ノード・345矩形を検査した。画面外への横はみ出し・hidden/clipによる欠け・balance指定はいずれも0。主要操作81件はすべて44 CSS px以上で、64ルールを保持した。閉じた詳細は意図した非表示であり、表示状態の検査とは分けている。

200%のまま、IMEの検索2件、分野との交差1件、存在しない語の0件案内、リセット64件、3つの長い詳細の展開、導入コマンドと依頼文のコピー成功を確認した。本文・見出し・メニュー・検索・導入の画面も確認した。デザインの崩れは見つからず、製品のHTML/CSS/JavaScriptや配布物を修正する必要はなかった。

実測値、倍率判定、DOMの読取コードと負例の結果は[zoom-200-evidence.json](zoom-200-evidence.json)へ保存した。ブラウザで実測する前の指定値や、静的な検査だけを成功にしていない。これは今回の公開版とChromeの実ページ拡大の記録であり、文字だけの拡大・別OS・他ブラウザの結果ではない。

確認後は対象サイトを100%へ戻し、DPR2・1920×873 CSS pxへの復元を確認して作業用タブを閉じた。共有Chromeでフォーカスの切替が重なった初期の試行は成功に含めず、対象URLを前面で照合してから一続きの操作で実倍率を設定した。終了時の前面タブも100%だった。新しいブラウザinstanceやworktreeは作っていない。

今回は実UIの確認と記録のみで、製品の挙動を変える開発変更はない。形式モデルの追加は対象外とし、実Chromeの倍率・矩形・操作、倍率判定の正例/負例、ソースと配信物の固定比較を代替確認とする。build/test・Biome・日本語lint・機密検査、通常のPR/CIを維持する。配信物が同じ場合は同じWorkerの再配備を行わず、現行本番の読み戻しで確認する。
